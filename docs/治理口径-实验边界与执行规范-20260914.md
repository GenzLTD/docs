## Owner 原始口径（2026-09-14）

> 对 GenzLTD 中的事务进行处理。聚焦于明确治理边界与执行口径，不扩张产品线，不将本地实验写成组织事实。
> 我们保留合规底线，但不压制创新推进；成员可在本地结合各自语料与环境验证 pgvector / 智能化构想，但必须明确标记为实验性验证，不能直接升级为正式业务结论。
> 当前阶段仍应维持 dsh-bridle 的冻结边界，pgvector 仅作为技术准备项而非业务承诺，任何影响组织口径、对外承诺或正式落地的事项，均需 owner 最终拍板。
> 本次落文的核心目的，是把"允许试验、禁止伪装事实、保留创新、守住合规"落成统一口径，并为后续 PR review / merge / 执行事务提供清晰依据。

## 一、四句总纲

| 原则 | 含义 | 执行要点 |
| --- | --- | --- |
| 允许试验 | 创新验证不设审批墙 | 成员可在本地结合各自语料与环境验证 pgvector / 智能化构想 |
| 禁止伪装事实 | 本地实验 ≠ 组织事实 | 实验产出必须显式标记「实验性验证」，不得直接升级为正式业务结论 |
| 保留创新 | 合规底线不压制创新 | 试验自由与标记义务并行，不因合规收紧而冻结本地探索 |
| 守住合规 | 底线刚性 | 公安联网备案、增值电信许可、数据合规等底线事项不变（见 issue #16） |

## 二、治理边界

- **不扩张产品线**：本阶段不新增正式产品线。
- **dsh-bridle 冻结边界维持不变**：以 [ADR-0011](adrs/0011-dsh-bridle-freeze-career-cosmos.md) 为准，任何解冻讨论走 ADR 修订流程。
- **pgvector 定位 = 技术准备项，非业务承诺**：本地装机、选型、落点建议均为技术储备；不进入对外承诺、不进入产品路线图的事实表述。

## 三、执行口径

1. **实验标记义务**：本地实验产出（文档 / 代码 / 数据）在标题或 Status 行注明「实验性验证（个人本地环境，非组织结论）」。
2. **归档路径**：实验内容归入本库时，须以草稿/实验稿命名（参照 `草稿-*` / `研讨稿-*` 惯例），不得以事实口吻写入决策文档或索引表。
3. **升级通道**：实验结论要成为组织事实，唯一路径 = owner 拍板 → ADR / 决策文档落文 → PR review。
4. **owner 拍板范围**：凡影响组织口径、对外承诺、正式落地的事项，一律 owner（zervi-genz）最终拍板，任何成员不得单方宣布。
5. **PR review / merge 依据**：评审时按本口径判断——实验性内容不得以事实口吻表述；业务承诺类表述必须有 owner approval。

## 四、对存量文档的影响

- 无追溯改动：既有文档不做回溯性修改。
- 本口径自生效时刻起适用于全部新增文档与 PR。

## 五、修订方式

- 本口径修订由 owner 拍板后走 PR 流程，保留完整历史。
