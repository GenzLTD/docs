# 环境一致性说明（本机 vs Codespace，及 CI 接入）

> 记录一次真实的验收教训，供后续成员参考。写于 2026-09-06。

## 背景

本仓以 Codespace 作为统一文档编辑环境（见 ADR-0006），`.devcontainer` 的 `post-create.sh` 会预装 MkDocs、Material 主题与 Mermaid 支持。

但本仓此前**没有 CI**，`mkdocs build --strict` 的验收只能依赖提交者自己的环境。

## 事件经过

ADR-0008（文档单真源化）迁移验收时，需要提交 `mkdocs build --strict` 通过的证据。负责的 owner（szpeter2026）在**本地 Windows 机器**上临时安装了 mkdocs + mkdocs-material + mkdocs-mermaid2-plugin 来完成构建。

过程中暴露两个问题：

1. 本地环境与 Codespace 的 devcontainer 环境**并非同一套**——本地装的是 mkdocs-material 9.7.7，而 Codespace 由 `post-create.sh` 决定版本，两者未对齐；
2. 本地构建只能证明"在这台机器上能构建"，**不能证明团队标准环境能构建**。

## 结论与决策

- 文档构建验证应以 **CI（GitHub Actions）的 `mkdocs build --strict` 为唯一金标准**，不再依赖任何个人本机环境；
- 本仓接入 CI（`.github/workflows/docs.yml`），在 PR 与 main 推送时自动构建；
- 成员本地 / Codespace 的构建仅作自检，最终以 CI 结果为准。

## 影响

- 新增 / 修改文档的 PR，需 CI 的 build 检查通过；
- 若 CI 与本地结果不一致，以 CI 为准，并排查依赖版本差异。
