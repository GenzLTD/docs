## 3. 关键发现（对设计输入的映射）

### 3.1 企业侧已有可用底盘

- **数据出口半成品**：`enterprise_routes` 已给 `GET /v1/enterprise/candidate/<id>` 附加 `trust_profile.attestations`（MANIFESTO :362 标注为"预留、前端未消费"）；PlanetX 闭环审计列为 P0 缺口。→ 企业侧"档案可信视图"是**已存在架构、未产品化**，不是从零立项。
- **档案中间服务商模型**：转录中有完整产业断层论证（学籍/技能/人事档案电子化"存证查询=成本中心"→ looma 把档案当**可验证声明被引用**而非附件，按验证量分润）。→ 指向"人才档案管理 + 验证服务"作为企业侧产品形态候选。
- **HR 端消费的应是凭证层而非几何层**：MANIFESTO/TRUST_LAYER 一致强调 HR 看到的是"带行为证据链 + credential 交叉验证的信任档案"，不是社交路径。

### 3.3 红线与必须避免的坑

1. **几何层 ≠ 信任**：社交距离/六度路径**不得**作为评价可信度或 HR 可见信用依据；MANIFESTO 已列"废弃 `trust_score(degrees)`"待办。→ 六度类算法只可作推荐链/验证池/关系上下文，不能当评价可信度本体。
2. **自我背书 ≠ 真实证据**：windows 审计曾发现"舰队 create/join 无条件写 `consensus_confirmed: True`"被判定为自我背书而非真实协作证据——**互评可信度验证的核心是防自证**（评价须来自独立第三方或双向对证）。
3. **匿名 ≠ 不可审计**：匿名（或伪匿名）只是"评价者身份对评价对象不可见"，评价本身仍需可溯源、可审计、可撤回；匿名若变成不可验证，就是不可信评价（本命题要回答的正是匿名与可信度之间的机制取舍）。
4. **图级脱敏缺口**：真实人才简历的人际边（如共事关系）存在**图重识别**风险；字段级脱敏（`looma compliance/redact.py`）不足以覆盖，立项需含图级脱敏评审。
5. **合规框架沿用**：PIPL/GDPR/Tier 0-2 同意与科研库隔离，直接套 `PLANETX_RESEARCH_PROPOSAL.md` §5-§6 与 ADR-0009。

## 4. 已知缺口（尚未有任何来源覆盖）

1. **"匿名评价"与"互评"尚无产品层设计**：全库检索 0 命中"匿名评价"作为已记载概念——它只以「双伪匿名科研 ID / candidate_alias 匿名展示」的形式存在于契约层，缺产品化语义。
2. **评价来源仍缺**：真实简历侧只有"可评价关系（共事/合作）"，没有评价内容；六度类资产填不了这个洞。候选补法（待决策）：产品互评采集 / 背调引入 / 权威档案锚定，均未立项。
3. **评价边 ≠ 现有社交边**：`graph_builder` 建的是无向无权"共属/推荐"邻接；人际评价边是**有向、带类型（认可/悼念/批评）、带强度、带时序**的边——需要新数据模型，不能直接复用。
4. **代码存量归属不清**：上述 trust/credential/科研协议实现是否就是 `GenzLTD/looma-zervi` 官方主线的当前代码（本机工作树有未提交改动），需要并入立项前提另行核验。
