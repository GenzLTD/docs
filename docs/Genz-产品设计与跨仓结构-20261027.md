## 0. 这份文怎么用

两份旧文分工已经乱了。结构文把「某一时刻的 PR、钉和路由」写成了项目结构，同一天就需要勘误。差距单适合跟踪，不适合当成产品设计。

本文只写换一支提交也不会改口的规则，外加一张标明日期的钉一览。钉一览过期时，改差距单，不改下面各节的规则。

对照 Win 侧 2026-10-27 更新版差距单之后，本文做了这些取舍：

- 采纳「终端不是一个仓」。人们说的终端是五件分开的东西。差距单 §3 不再用一个百分比概括终端，本文同样不概括。
- 采纳 `planetx-miniprogram` 是从 looma 切出的微信壳，13 页、底栏 3 项，仓库里的接口源为空。它不是 Genzer-Terminal 里那 3 页登录壳。
- 采纳穿戴工程在 `YeDall3.0.1`，设备契约的对象是灯、锁和影子。本机只读镜像停在 2026-05-29，没有再对 GitHub 尖端。CATALOG 里另有一仓叫 `Ctrl4U`（鸿蒙骑行）。两处都还没有格契价值轴的钉。
- 不采纳差距单 GAP-05 里「Act 1 从不调用 `add_imprint`、游客在 `domain_engine.py:388` 被挡住」的路径描述。looma `main` 上，登录用户的 Act 1 选择路由会写印记并尝试发信号；空用户直接返回空。`/v1/ask` 那四个上下文字段仍然没有赋值方。开发库有没有行，仍由差距单复跑。
- 不采纳「终端全部分支都没有 `app/community`」。`main` 和线上没有这一页。未合并分支 `fix/planetx-growth-entry` 上有公开说明书。
- 差距单 §1.3 把 zervi-rust `main` 写成 `4d7e9ce`，§1.5 写成 `4d0e1e1`。以求职仓自己的 `contracts/gfcc/SOURCE.json` 为准：钉的是 L0 1.3.0，信号目录里没有 `value_axis_choice`。
- 差距单 §5 的 M2 仍把「终端与内核」写成一张皮。那和它自己的 §1.5 冲突。接通顺序以 §1.5 为准：先选定穿戴消费哪一份契约，再谈联调。
- 小程序工作区里若用 `skip-worktree` 把接口源指到某一台机器，那是本机私改，不是仓库结构。仓库提交里的源是空字符串。

## 1. 产品是什么

Genz 把三件事放在同一套契约上。它们还不是一条已经收钱、已经有活人的闭环。

1. **PlanetX**：一个人用叙事走完一个生活域，留下自己的选择。当前只把职业域接到 SaaS 试用入口。
2. **格契（GFCC）**：社区营造的契约层。人是目的，AI 是放大器。五个一等端口记住围坐、身份与价值轴、记忆、共议和贡献。八角梯是身份上的成长阶段，营造师是擅长做什么，两者不是八个服务。
3. **求职与会员**：职位分、简历、定价和档位。职位分可以读价值轴，不能写价值轴，也不能把轴上的整数写回分数。

跑一段时间之后，什么算格契起作用了，只看价值层的五条，不看管道是否返回 200：

1. **记得住**：七库记录被后续议题或行动引用。
2. **协商得了**：凡 `consensus_verified` 的提案，谁评、依据什么，可以完整追溯。
3. **兑得现**：`contribution.fulfilled` 回写到 `identity.capability_trace`，并且重启之后还在。
4. **人往高处走**：有人走过 `observer → participant → proposer`，每一级都有证据。
5. **AI 不抢戏**：AI 观察可以当证据，不能单独把人抬上角色。

这五条今天还没有一场具名真人的证据。契约写进 `main`，只说明管道能转。

| 仓 | 负责 | 不负责 |
|---|---|---|
| `GenzLTD/gfcc` | 契约真源和内核。L0 JSON、信号信封、五端口、`POST /v1/ask`、`POST /v1/signal-ingest`、`POST /v1/identity/value-axes` | 不画页面，不收银，不发会员档 |

| `GenzLTD/YeDall3.0.1` | 另一条产品线：鸿蒙工程 `frontend/yedall-harmonyos-ctrl4u`（包名 `com.yedall.ctrl4u`）、`frontend/yedall-harmonyos`，以及 `iot-device-service` 等设备服务 | 不是 Genzer 网页站，也不是围坐。设备契约写的是人对灯、锁、影子 |

`gfcc.terminal` 是内核里的一种模式：必选端口收成身份和记忆。它不是一台设备，也不是上面任何一个仓。

GitHub 组织 `GenzLTD` 是契约和产品代码的写作汇合处。Gitee 上的同名仓是滞后镜像。本机检出的分支经常比两边都旧。看「现在的契约」时读 GitHub 上的 `main`，不读桌面上碰巧打开的工作树。

`CATALOG.md` 是 2026-09 的血缘索引。它把 `YeDall3.0.1` 标成 IoT 平台，把 `DemoPPI` 标成早期雏形。那些行解释仓库从哪来，不解释人今天从哪个门走进去。产品边界以本文为准。

## 3. 版本怎么读

四套数字不要并成一个「1.5.0」。

| 对象 | 意思 | 写在哪 |
|---|---|---|
| 内核软件 | `/health` 自报的程序版本。分支名里的 1.4.0、1.5.0 不是它 | `services/gfcc_kernel/pyproject.toml` |
| L0 契约 | `contracts/*.json` 里除信号信封以外的家族，含 `job_match.v1.json` | 各文件的 `version` |
| 信号契约 | `signal.envelope` 和 `contracts/signals/` | 信封自己的 `version` |
| 支付契约 | 会员档和 CN / US 通道。谁写档，谁是 looma 的 `update_user_tier` | `looma-zervi` 的 `backend/contracts/payment.v1.json` |

消费者钉的是格契的某一次提交，不是「最新 main」。刷新钉的办法是改该仓的 `contracts/gfcc/SOURCE.json` 和拷进去的字节，再走该仓自己的发布。预发钉在 Vultr 仓，不在服务器上改字段。

`main` 和未合并的钉版分支是两套现状。部署仓的 `main` 可以仍钉着旧家族，而某次预发流水线用的是另一条分支上的新钉。这种时候，机器上的内核和 GitHub `main` 上的钉不是同一句话。

## 4. 人怎么走

### 4.1 职业域

叙事引擎的六个域是：职业、身份、诗、信任、自我、迷雾。问询芯片的六个名字是：职业、学习、生活、社交、健康、创意。这两组不要并成一张表。名义二选一是差距单上的决策，本文不替那一刀拍板。

当前只开放职业域的 SaaS 出口：

1. 叙事走到该域该停的地方，先出现手写的第一幕收束。
2. 收束下面才是「看这一域的完整职业解读」。
3. 链到 SaaS 定价页，查询为 `src=planetx_domain`、`domain=职业域`、`region`、`campaign`（有裂变码才带）。
4. 落点是 T-space 定价页。
5. 「7 天」是页面文案。Stub 开通没有到期日。

自我域保持「开发中」。其它域不要照抄职业域这个按钮。

选职业域里的一个选项时，信号用这个选项自己的 `imprint_axis` 和 1–5 点，不用该域的默认轴。客人不成信号。`record_choice` 只记选择，不顺手写一条印记。

### 4.2 价值轴

三轴在人话里是「钱多、事少、离家近」，在契约里写成：

| 轴 | 人话 | 职位分上的读法 |
|---|---|---|
| survival | 钱多 | `salary_match` |
| freedom | 事少 | `culture_workload_match` |
| belonging | 离家近 | `location_match` |

规则：

- 只有 `planetx` 和 `system` 能写。`job_match` 只有 `identity.value_axes.read`。
- `identity.write`、通配、管理员档，都不等于写口。
- 内核交回原始快照。归一化留在匹配侧，不写回内核。不同用户的整数不能横比。
- 累加不在内核里封顶。
- 载荷白名单只有轴、点数、域、印记名、来源、时间。职位分字段进来即拒绝。`source` 必须是 `planetx`。
- 空用户的读返回 `null`，不因此创建画像。读不改变快照。
- 没配登录密钥时，价值轴口返回 503，不用空密钥把请求放行。
- 摄入要 HMAC。密钥留空只允许本地联调。未签名请求拒绝。

职位分区间锁在 `job_match.v1.json`。改 looma 的 `_clamp` 而不改这份契约，就是违约。匹配侧读三轴并进入那三项分数，是差距单上的事；分数区间本身不因价值轴这一刀而改。

### 4.3 印记在代码里从哪条路走

登录用户走 `/v1/narrative/engine/act1/choice` 时，路由调用 `add_imprint`，并尝试发出 `value_axis_choice`。T 空间前端调的是这一条。

空用户在 `add_imprint` 里直接得到空结果，发送函数看到没有用户就返回。客人走完剧情，不会在格契里留下轴上的点。

`/v1/ask` 会读取 `last_choice`、`choice_importance`、`session_num`、`interaction_count`。这些字段没有赋值方。问询那条路不负责把印记写进库。

跨域回声、涌现策略、收敛和 Act 5 清算，都依赖印记真的积起来。有没有积起来，看差距单上的复跑，不在本文宣布已经接通或已经全断。

六域审计和被恢复的 GDD 在 looma 的分支 `audit/planetx-six-domains-20261025` 上，不在 `main` 上。

### 4.4 围坐

首页「探索社区」进入发现页 `/discover`。未登录时发现页把人送到登录。公开说明书不在 `Genzer-Terminal` 的 `main` 上，线上 `/community` 也没有这一页。围坐入口是单独的门，指向 circle 站点。说明页不是围坐本身。围坐的可用性单独算，不把说明页或首页链接的完成当成围坐已通。

格契对围坐的定义：会场不是聊天室。草稿在视频，提案在地板，事实在合并。共识要过阈值，并且双向确认。AI 观察可以当证据，不能单独把人抬上角色。

### 4.5 会员、裂变和星际等级

这三套不要混：

- **会员档**：free / supporter / pro，以及支付契约里的区（CN / US）。
- **传播**：满员解锁广域扫描。试用点击不增加 `spread_count`，也不给邀请人升档。
- **星际等级**：经验公式。试用成功不加经验。游戏等级不是试用资格，也不改价。资料卡上的 Free / Silver / Gold 又是另一套。

海外站结账必须显式带账单区。区来自 `trial.region`，没有则回退 `BILLING_REGION`。不能在结账调用里写死 `US` 或 `CN`。省略区时，后端会按语言猜。

真实微信、Stripe、统一登录、跨区 `upgrade_token`，契约和文档里有位置，实现不在本文展开。`upgrade_token` 目前只出现在升级说明里。

### 4.6 人们叫做「终端」的五件事

| 人们说的 | 实际在哪 | 和价值轴门禁的关系 |
|---|---|---|
| 网页站 | `Genzer-Terminal`。站点 `www.genz.ltd`。仓内说明写明从 DemoPPI 演进，Ctrl4U 不在本仓 | 不收发 `value_axis_choice`。信号边界、匹配闭环、声誉页和链上 ActionType，在该仓 README 里仍是待开始 |
| 可穿戴 | `YeDall3.0.1` 的鸿蒙工程，包名 `com.yedall.ctrl4u`。CATALOG 另有独立仓 `Ctrl4U` | 产品叙事是设备和安全。没有格契 L0 1.5.0 的钉。刷脸不能代替真人围坐或真实收银 |
| 设备后端 | 仍在 `YeDall3.0.1`：`iot-device-service` 等。`docs/three-platform-device-contract.md` 状态为草稿（2026-05-17） | 模型是灯、锁、影子，不是「钱多、事少、离家近」 |
| 设备可信 | `planetx-tatha` | 差距单把它放在设备可信，不放在穿戴界面，也不放在价值轴写入。本文没有逐文件重读这一仓 |

穿戴端要接格契之前，先写明它消费的是价值轴契约、YeDall 设备契约，还是两者以及边界。选定之前，不把鸿蒙刷脸、网页邀请制或小程序模拟支付说成终端已经适配。

## 5. 身份和贡献记在哪里

内核默认把身份和贡献放在进程内存里。`identity` 端口的画像、`capability_trace`、价值轴选择，以及 `contribution` 端口的兑现记录，都是进程内的字典。进程重启，这些就没了。

会务流和记忆槽可以在 `STORE_PROVIDER=sqlite` 时落盘。这个开关不自动把身份端口和贡献端口变成同一张持久表。

所以「契约允许读价值轴」和「散会之后还记得这个人」是两件事。五条判据里的记得住、兑得现，卡在这里。

## 6. 部署认哪一钉

法兰克福是预发，不是新加坡生产。预发流水线换的是格契内核和 Tatha，并维护一个空的演练库。它不因流水线跑过，就替换用户正在用的 looma，不把 looma 指到 Postgres，不在这台机器上生成诗嵌入，不把内核端口对公网打开。

2026-10-27 的抽查记录写明：预发机上的内核进程是 L0 1.5.0 那一刀，未签名摄入拒绝，价值轴口在没有登录密钥时拒绝，演练库是空的。同一张记录写明正在跑的 looma 容器没有换成会发 `value_axis_choice` 的那一版。抽查通过只说明预发内核还是已拍板的那一刀，不等于闭环通过，也不等于可以收费。

这一刀能上预发，是因为部署仓的演练分支把钉改到了 L0 1.5.0。部署仓的 `main` 当时仍钉着 L0 1.3.0。所以「预发内核已经是 1.5.0」和「Vultr `main` 已经钉 1.5.0」要分成两句。求职仓的 `main` 也仍钉着 1.3.0 那一家族。

天翼、新加坡、腾讯云不在那张预发抽查里。

## 7. 改东西时先问哪一层

1. 这还是「人是目的，AI 是放大器」吗。不过这一问，不动契约。
2. 改 `gfcc/contracts` 的 JSON，并让同一家族版本一致。
3. 改端口提纲和内核。
4. 消费者改自己的钉，再谈部署。
5. 页面和收银最后动。

未知角色、空密钥、未配置的上游，都关掉，不放行。诗库门槛保持严格。
