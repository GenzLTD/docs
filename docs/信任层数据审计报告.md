# 信任层数据审计报告

> 审计日期：2026-09-10 · 审计人：szpeter2026（AI 辅助）· 状态：**发现稿，待团队评审**

## 一、摘要

对 Vultr 海外生产环境（`root@139.180.184.25` / hostname `genz-ltd`）的 looma.db 做了全量数据审计。结论：**信任层的「数据管道」已通，但「可信度验证」这个核心能力尚未真正实现**——证据是真实采集的，但结论（声明、状态、置信度）存在模板化、硬编码、证据强度脱节等问题。

## 四、核心发现（9 项）

### A. 数据真实性

**发现 1：52 条声明全是测试数据，无真实用户。**
用户名为 `SmokeTest`、`SmokeV2/V3`、`E2ESeeker`、`E2E PlanetX`、`E2E Resume Parse`、`E2E Jobs Match`、`测试用户-免费版/专业版`、`Recheck`、`MatchMate`、`Mate`、`LoopSeeker`、`ZerviTest` 等，全部是 E2E/冒烟测试账号。仅「嘟嘟」「穆蓝」两条疑似真实用户（有真实简历与职位匹配）。

### B. 签名机制

**发现 2：Ed25519 签名未真正落地，仅 9/52 条有签名。**
信任层的核心卖点是「可验证声明卡」，但绝大多数声明 `signature` 字段为空，第三方无法离线验证。签名机制未接入声明生成流程。

### C. 规则引擎

**发现 3：规则输出与设计文档（TRUST_LAYER.md）不一致。**
- 文档：「人格 sync → weak」；实际：人格（quiz）声明被标 **verified + 置信度 1.0**。
- 文档：「consensus → verified」；实际：舰队共识（fleet_consensus）声明被标 **weak**。

**发现 4：claim_statement 是固定模板，非从证据推导。**
42 条 quiz 记忆的人格结果是「星云艺术家」「黑洞程序员」，但声明统一写「在压力下倾向战略型决策」——人格类型与声明内容无法对应，说明声明文案是硬编码模板。

**发现 5：证据强度与结论脱节。**
quiz 答题记忆全部 `total_score=0, correct_count=0`（测试账号未答题），但对应声明仍被标 verified + 置信度 1.0。零分证据得出满分结论，逻辑矛盾。

### D. 证据采集

**发现 6：`consensus_confirmed` 字段被硬编码为 True（自我背书）。**
11 条 fleet 记忆无论 `create_fleet` 还是 `join_fleet`，全部无条件写 `consensus_confirmed: True`。**无真实双向共识，却全标共识确认**。印证 PR #11《人际评价边立项-可信度验证设计输入》§3.3 红线 #2 已记录的「自我背书而非真实协作证据」问题。

**发现 7：resume 解析不完整。**
12 条 resume 记忆 `skills_claimed` 有内容，但 `roles: []`、`years:`、`education:` 全为空。「可核验的职业经历与技能主张」声明里，「职业经历」实际是空的，仅有技能。

**发现 8：设计的三类证据通道只实现了一部分。**
TRUST_LAYER.md 设计「文字 / 对话 / 行为」三类通道，但 `ask`（对话）与 `share`（分享信号）session_type 从未产生任何 memory。对话分析、分享信号两条通道未实现。

### E. 契约同步

**发现 9：证据类型枚举超出契约。**
trust.v1.json 的 `evidence_type` 枚举为 `quiz/fleet_consensus/dialogue_analysis/share_signal`，但实际数据出现 `resume`（7 条）和 `match_scan`（4 条），契约未同步更新。

## 五、结论

| 维度 | 状态 |
|------|------|
| 数据采集管道（采集→存储→链接） | ✅ 通 |
| 证据→声明链接（evidence_refs） | ✅ 通（72/78） |
| 可信度**计算**（证据→可信结论） | ❌ 未实现（模板化、硬编码、证据强度脱节） |
| 可验证**签名** | ❌ 未落地（9/52） |
| 证据通道完整性 | ⚠️ 缺 ask / share |

**一句话**：信任层骨架已搭好，但「从证据推导可信结论」这一核心能力仍是空的。当前数据只能证明「管道通了」，不能证明「可信度被正确计算」。这与 PR #11 的判断一致——可信度验证目前是**命题**，不是**已实现的能力**。

## 六、建议（按优先级）

1. **P0 · 修复 consensus_confirmed 硬编码**：改为真实的双向共识判定（双方独立确认后才置 True），否则信任层失去根基。
2. **P0 · 落地 Ed25519 签名**：每条 attestation 生成后必须签名，第三方可离线验证。
3. **P1 · 校准规则引擎**：人格→weak、共识→verified，与 TRUST_LAYER.md 对齐，并消除「0 分给 1.0 置信度」的矛盾。
4. **P1 · claim_statement 去模板化**：从 evidence 真实推导声明内容，或明确标注为模板占位。
5. **P2 · 同步契约**：evidence_type 枚举补上 `resume`、`match_scan`。
6. **P2 · 完善 resume 解析**：补齐 roles/years/education 提取。
7. **P3 · 实现 ask/share 证据通道**：对话分析、分享信号。
8. **P3 · 用真实用户跑一次端到端验证**：验证上述修复后的可信度输出是否合理。
