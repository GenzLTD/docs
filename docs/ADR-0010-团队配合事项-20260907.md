# ADR-0010 落地：需要团队配合的事项

> 日期：2026-09-07 · 配套 [ADR-0010](adrs/0010-cn-wechat-pay-three-client-ops.md)（**Proposed，本文件不是 Accept 证据**）
> 取代 PR 上此前「本机 44 passed / 可以 Accept」回执。不提交验证代码，不把未入库工作区当验收。

本机 Win ServBay 只用来核对「现在缺谁」：工作区 `C:\ServBay\www\looma-zervi`，vhost `looma-zervi.local` 把 `/v1/` 反代到 `127.0.0.1:5200`。核对当时 Flask `:5200` **未在听**，微信商户环境变量 **未配置**。因此国内支付进不了场，需要下列成员配合。

---

## 1. 商户与主体 — `szpeter2026` / 财务

内地微信支付商户与香港 YEDALL 的 Stripe 沙盒不是同一套。没有商户号，本机无法走出码。

请提供（不要贴到公开 PR，写进生产/预发 `.env` 或安全渠道）：

| 项 | 用途 |
|---|---|
| 内地主体商户号 `WECHAT_MCHID` | API v3 下单 |
| 已绑定该商户的公众号或小程序 `WECHAT_APPID` | Native / JSAPI |
| API v3 密钥、证书序列号、`apiclient_key.pem` 路径 | 签名 |
| 开通 **Native 扫码**（第一单建议） | PC 验收 |

第一单建议 0.01 元 Native，不要从小程序 JSAPI 起刀（还要真实 `openid`）。

## 2. 公网回调与 ServBay — 运维 / `szbenyx`

微信没有 Stripe CLI。`WECHAT_NOTIFY_URL` 必须是公网 HTTPS，且与商户平台登记**同一路径**：

```text
POST /v1/payment/wechat/notify
```

不要再用文档里的旧路径 `/v1/payment/notify/wechat`。

请配合：

- 把预发/备案 API 域（或内网穿透）指到上述路径；
- 在本机 ServBay 把 `looma-zervi.local` 后端 `:5200` 和三端静态站点拉起来（当前 Win 上 API 未监听，无法做联调）；
- 回调验签失败时一起看商户平台通知与 Looma 日志，不改成 Stub 直升。

## 3. 契约文档路径 — `looma-zervi` 文档维护人

全部改为代码真源 `/v1/payment/wechat/notify`。  
`docs/STRIPE_SANDBOX_LOCAL_ACCEPTANCE.md` 若要当海外骨架证据，须先合入该仓 `main`；在此之前不要链进 ADR。

## 4. 三端可重复演示 — 前端（SaaS / PlanetX / 小程序负责人）

ADR 把「三端可运营」定为 **Accept 之后的交付**，现在不声称已人工通过。请各写一条可交给评委的步骤，放进 `looma-zervi` 验收文档（例如 `COMMERCE_CLOSURE_STATUS.md`），不要只写在聊天里：

```text
登录 → 支付入口或已付费态 → 一个受 tier 门控的产品动作
```

| 端 | 建议门控动作 | 现状（源码有接线 ≠ 已走通） |
|---|---|---|
| T空间 SaaS | 候选人池 / 职位发布 | 需本机 `VITE_DEPLOY_REGION` 不为 `SG`，走 CN 微信而非 Stripe |
| X星球 PlanetX | 付费权益或职业动作 | 需人工清单 |
| 小程序 | JSAPI 支付或已付费态 | 另需真实登录 `openid` + 支付授权目录 |
