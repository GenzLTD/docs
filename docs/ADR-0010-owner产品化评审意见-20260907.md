# ADR-0010 Owner 产品化评审意见

> 日期：2026-09-07
> 评审视角：Owner / 产品化与现金流
> 关联：ADR-0010「国内 Looma 微信支付 + 三端可运营」

## 一、评审结论

支付不是本阶段的附属验收项，而是产品生命线。三端支付拉通的价值，不是把 T
空间、X 星球和微信小程序做成三个同等成熟的产品，而是提前建立一条统一的现金流
管道，保留三个潜在变现入口。

因此，ADR-0010 的方向可以保留，但“可运营”的含义应从“功能全部完成”调整为：

> 三端能够接入统一身份、订单、支付回调和权益系统；每个端都可以验证自身的付费
> 假设；资源投入依据真实交易数据而不是预设判断分配。

## 二、产品与现金流关系

| 端               | 主要付费假设                                     | 初期验证重点                         |
| ---------------- | ------------------------------------------------ | ------------------------------------ |
| T 空间 SaaS      | 企业为人才连接、招聘效率或高级服务付费           | 企业是否愿意付费、复购或形成采购意向 |
| X 星球 / PlanetX | 人才或社群用户为职业探索、成长服务或会员权益付费 | 个人付费、留存和有效职业动作         |
| 微信小程序       | 国内用户通过低门槛入口购买轻量服务               | 触达、转化和支付成功后的权益使用     |

海外高端人才是核心供给和战略机会来源，但不应在没有数据前假定其一定是第一
付费方。企业、人才和小程序用户都可能成为现金流来源，产品应通过交易数据验证
谁真正愿意付费。

## 三、统一支付底座是必要条件

三端支付不应各自维护一套会员或订单逻辑。统一底座至少应保证：

```text
统一身份
  -> region / 货币 / 支付渠道
  -> 订单与支付状态
  -> 回调验签与查单
  -> tier / entitlement 权益
  -> 三端一致读取权益
```

需要特别防止以下问题：

- 一个端完成付款，另一个端无法识别权益；
- 同一用户在不同端重复购买或重复收费；
- 企业订单、个人订单和服务订单混用；
- 微信与 Stripe 的地区、币种、退款和权益语义不一致；
- 支付成功后无法对应到具体职业服务、人才连接或产品动作。

## 四、产品化取舍

三端支付管道可以并行建设，但三端的产品功能、运营投入和增长预算不应平均
分配。建议遵循以下顺序：

1. 先统一身份、订单、支付和权益模型；
2. 为三个端分别写出一个可验证的收费假设；
3. 用真实付款、转化、客单价、复购和获客成本比较三个端；
4. 出现稳定现金流后，立即把产品、运营和研发资源集中到表现最好的端；
5. 未产生交易证据的端保持最小可运营状态，不继续扩张功能。

“谁知道哪片云会下雨”在产品上应被转化为商业期权策略：先接通管道，再让真实
市场决定哪一片云形成降雨；但保留期权不等于长期平均用力。

## 五、与现有产品定位的关系

当前组合应明确为一个产品叙事，而不是四个并列产品：

- **T 空间**：企业侧商业产品和主要收入验证对象；
- **X 星球 / PlanetX**：人才触达、职业探索和社交裂变入口；
- **Looma**：画像、匹配、支付和权益所需的共用底层能力；
- **信任层**：跨境信息授权、隐私门控、推荐依据和审计能力。

核心市场机会是：在中国科技企业与海外高端人才之间，建立合规、可信、可解释
的职业连接。支付能力要服务于这个连接结果，而不是脱离业务成为单独的技术展示。

## 六、Owner 验收指标

ADR-0010 后续验收建议同时记录技术、交易和产品三类证据：

### 技术证据

- 三端使用统一身份、订单和权益模型；
- CN / US 支付渠道按地区正确路由；
- 支付回调、查单、退款和重复通知具备可追溯状态；
- 代码、环境和部署 commit 可复现。

### 交易证据

- 每端至少有明确收费对象和收费事件；
- 记录访问、付费转化、客单价、退款、复购和获客成本；
- 支付成功后发生可验证的权益使用或业务结果变化。

### 产品证据

- T 空间：企业人才需求到有效连接或招聘结果；
- X 星球：人才画像到职业动作或有效推荐；
- 小程序：低门槛触达到付费服务和权益使用；
- 三端结果能够回流 Looma，改善匹配与转化，而不是只增加注册量。

## 七、Owner 决策建议

本次评审不建议因为支付技术已验证就宣布产品已经成立，也不建议因为三端尚未
同等成熟而否定三端支付管道。建议正式采用以下决策句：

> 三端支付是统一现金流管道和商业期权，不是三条平均投入的产品线。团队先完成
> 可复用的身份、订单、支付和权益底座，再分别验证三端的付费假设；一旦真实交易
> 显示某一端形成更强现金流，资源立即向该端集中。T 空间负责企业商业化，X 星球
> 负责人才入口，Looma 提供共用能力，信任层负责跨境可信连接。

在完成统一底座和首轮交易验证前，建议 ADR-0010 保持 `Proposed`，并将“支付管道
已接通”和“某端产品已形成稳定收入”明确区分。
