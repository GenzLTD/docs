# 实证记录：诗词语料 → 人才共识与评价模型沙盘

> 状态：**实证记录（Proposed，待评审）** · 作者：szpeter2026（执笔：Dudu） · 日期：2026-09-09
> 一句话：**已归档的诗词门户语料没有浪费 —— 它以零合规成本验证了 T空间/Looma 最核心的机制假设：「同行共识 + 同侪评价」可以作为人才评估的可计算信号。**

---

## 一、为什么做这项工作（动机）

### 1.1 缘起

90 天聚焦决策（Career Cosmos 矩阵）中，**T空间（B2B HR SaaS）的变现故事**和 **Looma（AI 引擎）**都依赖同一个尚未实证的机制假设：

> 人才的"共识与评价"（同行认可度、同侪声誉）能否被结构化数据计算出来，而不是只靠人工背调？

直接拿真实简历验证这个假设有两个障碍：**合规风险**（PIPL 敏感个人信息）和**数据缺失**（我们手里没有带同行互评记录的简历库）。

### 1.2 沙盘选择：诗词语料

选择公开诗词语料作为沙盘，是因为它与人才评估场景**结构同构**，且零合规压力：

| 人才简历域 | 诗词语料域 | 说明 |
|---|---|---|
| 候选人 | 诗人（1,276 位档案 + 5,146 位作者） | 同源数据、不同目的的两次提取 |
| 职业时间轴 | 生卒年 / 朝代 | LLM 按时间节点推算出 1,200+ 位作者的"同时空交集" |
| 同行 / 同业 | 同时代诗人 | 朝代字段直接可算 |
| 作品与产出 | 诗集（78,656 首） | 存诗量 = 贡献度原始信号 |
| **同行互评** | **赠答唱和诗** | 见 2.2 节实测 —— 本沙盘最有价值的发现 |
| 滞后声誉 | 后世选本收录 / 和韵次数 | 可测试"声誉滞后"现象 |

### 1.3 与既有工作的关系

- 诗词门户按 90 天决策已**归档/暂停** —— 本工作**不复活该产品线**，只回收其语料资产；
- 与 Nazha 归口（dsh-bridle）共享同一条 RAG 基础设施，边际成本接近零。

### 2.2 关键实证：诗题中的"人际评价边"密度

对 78,656 首诗的标题做模式统计（繁简全量匹配）：

> **9,628 首（12.2%）是明确的"人际评价行为"**：《送》3,810 / 《贈》1,458 / 《寄》1,289 / 《和》1,209 / 《酬》650 / 《別》268 / 《哭》234 / 《懷》161 / 《答》154 …

**为什么这是核心发现**：人才评估最难的不是算产出，而是拿到"同行互评"数据 —— 简历没有互评，背调成本高且样本小。而诗题中的赠答唱和是**带署名、带时间、带情感强度（哭/悼 ≠ 送/寄）的同侪评价记录**，天然构成一张约 5,000 节点的同行评价图：

- **和/酬** = 平辈专业认可（对方写了，我回应）；
- **哭/悼** = 地位的公认信号（有人为你写悼亡诗，说明你是"大人物"）；
- **被赠/被寄的频率** = 被动声望（别人主动找你）。

### 2.3 检索能力实证（"时代 + 人名"原语）

| 查询类型 | 结果 |
|---|---|
| 事实型（人名/字号/朝代）："字太白的唐代诗人是谁" | ✅ Top1 命中（档案库与全集两种形态均通过） |
| 名句回查："大江东去浪淘尽的作者" | ✅ Top1 命中苏轼《念奴娇》 |
| 主题型（边塞/豪放/遗民） | ❌ 待主题标注补齐（DeepSeek API 打标，约 ¥2） |

事实型原语已达标 —— 这正是"按时间节点定位人物"的基础操作。

### 2.4 诚实边界（未验证部分）

- 两批作者名交集实测仅 257 人精确同名（占第一批 20%；繁简归一后会更高）→ **合并是"互补可合"，不是 1:1 拼装**；
- 同时空交集的**文学史复现校验**（如李白-杜甫 744 年相识）尚未执行；
- 声誉中心度 vs 文学史公认地位的一致性检验尚未执行。

## 三、如何推动 90 天目标

### 3.1 对 Career Cosmos 四块拼图的直接贡献

| 拼图 | 本工作提供的弹药 |
|---|---|
| **T空间（变现）** | 「同行共识评分」机制假设获得实证路径 —— B2B HR SaaS 的差异化卖点：不只匹配关键词，还能算"同行认可度" |
| **Looma（AI 引擎）** | hybrid RAG 管线已验证可处理异构数据源；评价图提取是 Looma 评估引擎的下一个可执行模块 |
| **信任层（护城河）** | "敏感语料分级 + 脱敏闸门"架构已在沙盘中定义（Tier 1 公开上云 / Tier 3 本地+脱敏）—— 与 ADR-0009 隐私门控同构 |
| **BP 故事** | 融资时可讲：*我们的同行评价算法已在 5,000 人物、78,000 件作品的真实数据上完成沙盘验证* —— 有数据、有脚本、有报告 |

### 3.2 对 90 天硬动作的映射

- **硬动作 1（BP）**：本记录可直接成为 BP 技术差异化章节的素材（1 页图 + 12.2% 评价边数据）；
- **硬动作 4（技术欠债）**：零新增人力 —— 全部工作由 AI 助手在既有机器上完成，边际成本 < ¥5（含 API 打标预算）；
- **不新增产品线**：严守"聚焦才有力量"原则 —— 这是**资产回收**，不是新开摊子。

### 3.3 建议的下一步（不承诺、按资源取用）

1. 诗题评价边 → 结构化图数据（作者→动词→对象），纯规则可做，1 天工作量；
2. 同时空交集复现校验（对文学史 20 组已知共识）；
3. 若 T空间评分模型立项，沙盘结论直接迁移为设计输入。
