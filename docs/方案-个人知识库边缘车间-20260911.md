> 状态：**方案（Proposed，待 CODEOWNER 评审）** · 作者：`szjason72` · 日期：2026-09-11  
> 机器基线：Win `HUAWEI`（C/D/E 实测 2026-09-10～11）  
> 一句话：**只做能指着路径说清的个人知识库——D 盘出料、C 盘车间并落热库、天翼只加工门控放行的批次、E 盘只归档；不是第二大脑，不是 90 天产品，不复活 bridle 产品化。**

## 一、数据流（钉死）

```text
D:  语料真源（只出料，不接回写）
        │  扫描 / 切块（本机）
        ▼
C:  车间 + 热库（脱敏、门控、Chroma、SQLite、本机问答）
        │  仅「判定允许」的批次
        ▼
天翼  加工（embedding / 回归 / 无 PII 批处理）
        │  产物回写
        ▼
C:  热库更新（本机可查）
        │  完成后打冷快照
        ▼
E:  只归档（bundle / 日期目录），不参与运行时
```

| 盘 | 角色 | 本机实测（2026-09-11） | 禁止 |
|---|---|---|---|
| **D:** Work，ReFS，空约 258 GB | 语料真源。对齐 DemoPeter `PROJECTS_ROOT=D:/` | 已有工作文档，不必再复制一份 | 当作 Chroma persistent 盘（ReFS + 热库） |
| **C:** NTFS，空约 259 GB | 车间与热库：`DemoPeter`/`Nazha` 运行时、Chroma、SQLite、Ollama、venv | Ollama 已占约 5.7 GB；`C:\Users\HUAWEI\DemoPeter` **当前不存在**，须从 E 还原 | 把 USB 盘路径写进 `CHROMA_PERSIST_DIR` |
| **天翼** `/data/gfcc` | 已放行批次的加工与同树对照（已有 `gfcc-demopeter` :5220） | 见 Nazha 归口文 §2.2 | 上传 D 盘原片 / 简历 / L0；当第二块数据盘常驻原文 |

## 三、实现范围（你能理解的那一段）

可验收的个人知识库 = 下面四句同时成立：

1. **问得出处**：问题能命中 D 盘或已导入文档的路径/标题，而不是「像有」。
2. **本机可答**：未脱敏问答走本机 Ollama（与 ADR-0011 同口径）；embedding 模型与建库时一致（指南：`nomic-embed-text` 与 `merged_chroma` 绑定）。
3. **坏了能还原**：E 上有带日期的冷副本（项目树 + 不可再生的 `szpeter2026.db` / 配置）；不依赖 GitHub 网页。
4. **未脱敏不上云**：上天翼的批次必须能指出门控依据（规则 SHA 或书面放行清单）；L0 / 简历 / D 盘原片不上传。

不做：多端热同步人格、自动整理一生、用天翼当第二 Chroma 真源、把实验室沙盘语料灌进个人库。

## 四、分阶段（Accept 之后才排期；现在不构成承诺）

### P0 · 还原车间（本机，无天翼）

1. 按 `E:\DemoPeter_重构指南.md` 将项目拷到 `C:\Users\HUAWEI\DemoPeter`（**不**把 `CHROMA_PERSIST_DIR` 改到 E:）。
2. 重建 venv；确认 Ollama 模型与 `.env` 一致。
3. Web 改 **5220**（避开 Looma 5200）。
4. 验收：本机打开面板；至少 3 条问句能回到 D 盘或 `knowledge_base` 的路径（可手记，不进聊天贴原文）。

**P0 失败则停止**，不上天翼。

### P1 · 门控放行清单

1. 列出拟加工对象的类别（公开/已脱敏/内部工作文档/L0）。
2. 仅前两类可进天翼批次；内部工作文档默认留 C；L0 禁止。
3. 每批记录：时间、规则 pin（`genz-verify` / `wukong-core` SHA）、文件清单哈希、经手人。
4. 验收：抽一包「应拒绝」的样例（含手机号/邮箱类）不得出现在上天翼的清单里——对齐实验室「注入违例当黄金集」，不复用被测脚本当唯一证据。

### P2 · 天翼加工 → 回写 C → 归档 E

1. 天翼只跑放行批次（embedding / 回归测试）；**不**在云上持久化 D 盘原文。
2. 产物回写 **C** 热库；核对条数/模型名，不一致则拒绝合并。
3. 然后 `E:\backup\projects\demo-peter\<日期>\` 收冷快照或 bundle；不把 `.venv` / Ollama 模型拷上移动盘。
4. 验收：拔掉 E 后，C 上问答仍可用。

### P3 · 黄金断言（可选，跟实验室同构）

把「问句 → 必须命中的路径/标题」作成小黄金集，CI 或本机脚本 **非零退出**。模式对齐 `szjason72/genz-verify` 的 `scripts/assert-m2-golden.py`（判定可复现，绿灯绑断言）。实现落在 `GenzLTD/Nazha` 或本机 DemoPeter 测试，**不**把黄金集写进 docs 当语料。

## 六、资源判断（为何说 C/D 够车间、内存不够皮层）

| 项 | 结论 |
|---|---|
| 磁盘 | 还原 DemoPeter（约 12 GB + 1.2 GB venv）远小于 C 剩余约 259 GB；D 不必复制语料 |
| 内存 / 核显 | 约 16 GB + Intel UHD：单开 Ollama + 本机问答可行；全盘随时重嵌 + Agent 皮层不可作为本机目标，故重活上天翼且仅放行批次 |
| GitHub 网页/443 | 不稳定；薄实验室仓已有 Gitee 私有镜像。个人库热库以 C 为准，不以 GitHub 为运行依赖 |
