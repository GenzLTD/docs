# Career Cosmos 90 天聚焦决策：调研与执行建议

> 文档性质：评审建议，不替代《聚焦决策-Career-Cosmos-90天.md》或已批准 ADR。
>
> 调研日期：2026-09-07

## 一、结论摘要

当前聚焦方向是合理的，但 90 天清单同时包含融资、产品、支付、商标和多项许可，容易把四条产品线重新做成四个项目。

建议将 90 天目标收敛为：

> **以 T 空间为唯一商业验证主线，以 X 星球为增长入口，以信任层为差异化证据，Looma 只作为底层能力；在 90 天内获得真实用户、真实业务和可复现演示证据。**

成功标准不应是“完成了多少建设事项”，而应是：

- 至少 3 家目标企业访谈；
- 至少 2 家设计合作客户；
- 至少 1 家付费试点或明确采购意向；
- 1 条可复现的国内支付闭环；
- 1 套可审计、可回放的信任层演示；
- 1 套不依赖个人电脑和临场修改的融资 Demo。

## 二、对四块拼图的建议

当前 T 空间、X 星球、信任层和 Looma 的关系，应从“四个产品”改写为一个产品叙事：

| 层次 | 定位 | 90 天要求 |
| --- | --- | --- |
| T 空间 | 唯一商业主线，面向企业买方 | 拿到试点、意向或付费证据 |
| X 星球 / PlaneX | 用户入口和增长实验 | 验证用户能到达核心职业动作 |
| 信任层 | 可信和合规的差异化能力 | 展示规则、拒绝、人工复核和审计回放 |
| Looma | 共用底层能力 | 只交付主线所需的最小 API 和数据契约 |

对外融资材料应首先回答“谁付钱、为什么现在付钱、付钱后持续使用什么”，而不是同时讲四条产品路线。

## 三、建议重排 90 天硬动作

### 第 1-30 天：客户与边界

- 确定一个企业买方、一类用户和一个核心场景；
- 完成 3-5 家目标企业访谈并记录可验证结论；
- 确认 T 空间最小闭环，不再并行扩展新产品线；
- 绘制支付、职位、简历和测评数据流；
- 形成“业务动作 -> 备案/许可/合同/隐私要求”矩阵；
- 启动商标检索和申请，但不把商标申请当作产品进展。

### 第 31-60 天：最小试点

- 交付 T 空间一个可演示的企业工作流；
- 让至少 2 家目标客户实际试用；
- 记录激活、核心动作完成、复用和反馈；
- 完成信任层的最小回放链路：输入、判定、人工复核、版本和结果；
- 完成测试环境支付闭环，并明确与生产或商户沙箱的差异。

### 第 61-90 天：融资证据固化

- 固化付费试点、采购意向或可核验的客户证据；
- 完成三端固定演示步骤和验收记录；
- 完成 BP、财务模型和融资数据室；
- 对外材料只使用已验证指标，不把计划、代码骨架或 Test Mode 结果写成已运营收入。

## 四、支付验收建议

ADR-0010 将国内微信支付和三端可运营作为技术欠债收敛方向，这个方向可以保留，但验收应明确分层：

1. **代码层**：CN 区 provider、金额、下单、回调验签、查单和 tier 升档均有自动化测试。
2. **环境层**：记录环境类型、商户主体、商户号、API v3 证书、回调域名和代码 commit。
3. **业务层**：真实或商户沙箱支付后，账户权益确实发生变化。
4. **演示层**：三端各有固定的“登录 -> 支付入口或已付费态 -> tier 门控动作”步骤。

Stripe Test Mode 可以作为计费骨架证据，但不能替代国内微信支付运营证据。微信支付官方资料将 API v3 签名验签、回调报文解密、回调通知和商户证书列为独立接入环节，不能只以接口返回成功作为运营闭环。

## 五、合规事项不要默认全部是硬前置

`ICP B25`、小程序备案、`EDI B21` 和人力资源服务许可证是否需要，取决于实际业务流程，而不是产品名称。应先逐项确认：

- 是企业内部 SaaS，还是面向公众的信息平台；
- 是职位展示，还是经营性人力资源服务或人才撮合；
- 是否发生平台交易、在线结算或第三方商户行为；
- 是否处理简历、身份、测评和跨境个人信息；
- 哪个主体提供服务并承担合同、客服和数据责任。

建议把许可证任务拆成：

| 事项 | 处理方式 |
| --- | --- |
| 业务流程和数据流 | 90 天内必须完成 |
| 备案/许可适用性判断 | 90 天内取得书面结论 |
| 已确定且影响上线的许可 | 纳入上线前置条件 |
| 尚未触发或与当前 MVP 无关的许可 | 不占用主线交付资源 |

不要在没有业务流程和主管部门确认的情况下，把许可证名称直接写成已确定的硬交付。

## 六、信任层应改成可演示指标

ADR-0009 已将近期承诺收敛为信任层。建议用以下证据替代“AI 大脑”式叙事：

- 同一输入是否得到稳定 verdict；
- `allow`、`redact`、`deny` 是否可追溯；
- policy bundle 是否锁定 commit；
- 人工 override 是否留痕；
- 是否可以回放完整决策；
- 误拒、漏放和延迟是否有记录。

最小演示链路：

```text
用户输入
  -> 隐私/跨境策略判断
  -> allow / redact / deny
  -> 人工复核
  -> 版本化记录
  -> 可回放审计
```

## 七、建议补充的融资验收指标

“融资 300 万、出让 5-10%”应补充可执行假设：

- 目标投资人和接触数量；
- 目标客户和设计合作数量；
- 试点转付费的判断条件；
- 用户激活、核心动作完成和复用指标；
- 资金用途与 90 天里程碑的对应关系；
- 对外材料中哪些是已验证事实、哪些是 Proposed、哪些是远期路线。

融资 Demo 的最低可信标准是：客户或用户已经使用过、核心路径可以复现、数据来源可解释、未完成事项被明确标注。

## 八、风险判断

### 高风险

- 同时维护 B2B、B2C、底层引擎和信任层，导致没有一个产品真正完成；
- 把 Stripe 测试、代码测试或页面骨架描述成国内可运营收入；
- 在未锁定权威仓库、分支和 commit 的情况下使用本机未提交代码作为验收证据；
- 许可证适用性没有经过业务流程和主管部门确认。

### 可接受风险

- 商标注册尚未完成，但已完成检索、申请和品牌使用风险控制；
- 微信真实商户凭证尚未到位，但支付代码、沙箱条件和上线阻塞项被明确分层；
- X 星球暂时作为增长实验，而不是要求与 T 空间同时达到商业化成熟。

## 九、建议的决策句

建议将 90 天决策补充为：

> 未来 90 天只用一个企业场景验证 Career Cosmos 的商业成立性：T 空间负责形成付费证据，X 星球负责验证用户入口，信任层负责提供可审计差异化，Looma 只交付上述路径必需的底层能力。支付、商标和许可按上线阻塞程度排序，不以完成清单数量代替客户和收入证据。
