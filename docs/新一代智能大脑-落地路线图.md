## 三、各节点验收标准

### M0 架构蓝图 ✅
- **交付物**：`新一代智能大脑架构设计.md` v0.2（八大决策 + 业界参考）
- **验收**：八大决策明确，团队评审无阻塞性异议。

### M1 认知偏差检测 PoC ✅
- **交付物**：`genz-brain-mvp/`（门控钩子 + 轨迹记录 + 对比验证）
- **验收**：`python main.py` 跑通；门控判定正确（L0_PII 跨境 deny、L1 redact、public allow）；verify 能检出偏差（已检出 2 条）。

### M2 认知内核本体 ⏳（下一个）
- **目标**：Wukong Layer0/1/2 落地为可编程世界模型，替换 PoC 里的手工转录。
- **交付物**：
  1. 规则配置化——PyYAML 直读 `policy_rules.yaml`，不再手工转录 RULES。
  2. 完整 Layer0/1/2 本体加载（layer0/1/2 三个 json 全量解析）。
  3. 门控与 zervi-looma（Rust）行为对齐。
- **验收**：任意字段 → 隐私分级 → 跨境 verdict 全链路自动判定；同一输入，Python 门控与 zervi-looma 判定一致。

### M3 记忆层三层化（决策③⑦）
- **目标**：cortex-mcp 改造为三层分布式认知记忆。
- **交付物**：
  1. 记忆写入支持命名空间（device / edge / cloud）。
  2. 记忆 metadata 对齐 Layer0/1/2 canonical 字段。
  3. 上浮/下沉同步协议（脱敏共识子图才上云）。
- **验收**：L0 PII 记忆永不出现在 cloud 命名空间；设备/边缘命名空间各自可独立检索、断网可用。

### M4 编排 + 五槽 + 能力端口（决策①④⑤）
- **目标**：LLM Agent 编排 + 五槽 Runtime + 能力 MCP 化。
- **交付物**：
  1. 编排层——LangGraph / PydanticAI（或 DeepSeek Harness）跑通 Agent loop。
  2. 五槽落地——ctx.llm / tools / session / policy / store 注册表。
  3. 8+ 能力端口注册 MCP 工具。
- **验收**：给定一个自然语言任务，Agent 能自主选工具、多步执行、反思重试，返回正确结果。

### M5 边缘小脑（决策⑥）
- **目标**：zervi 终端机跑本地 Agent。
- **交付物**：边缘运行时（Rust/Go）+ 端云路由。
- **验收**：断网时终端机仍能完成本地推理；联网后轨迹自动同步到边缘/云端。

### M6 端到端闭环（全部）
- **目标**：黑匣子双组件接入真实运行的 Agent。
- **交付物**：集成系统（编排 + 认知内核 + 记忆 + 能力 + 边缘 + 偏差检测）。
- **验收**：真实 Agent 运行一周，黑匣子记录全部认知轨迹；verify 能报告偏差（违规操作 + 偏离共识的认知漂移）。

## 四、依赖关系与推进顺序

- **M2 必须先行**：认知内核（Layer0/1/2）是其余组件的"公约数"，记忆对齐、门控、共识评分都依赖它。
- **M3 依赖 M2**：记忆 metadata 要对齐 Layer0/1/2，先有本体才能对齐。
- **M4 可与 M2/M3 并行**：编排层、五槽、工具 MCP 化相对独立，可并行推进。
- **M5 依赖 M3/M4**：边缘小脑需要记忆分层 + 编排层就绪。
- **M6 依赖全部**：最后集成 + 认知偏差检测完整形态（大数据比对）。

---

## 五、验收方式

- 每个节点交付「可运行产物 + 验收证据」（运行输出 / 测试用例 / 比对报告）。
- 认知偏差检测（决策⑧）不追求"一次通过"，而是「边跑边积累偏差案例」，验收看**机制是否跑通**，不看**是否零偏差**。
- 路线图随实践迭代，节点完成后更新状态，供团队持续对照。
