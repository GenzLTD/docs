### 3.1 表数口径与 dev 前瞻增量（2026-09-11 实测复核）

> 触发：核对本机 dev 相对生产的表数增量到底是什么。全程只读（`file:…?mode=ro`），未改任何库。
> 口径：表数一律按**业务表**计，**排除 SQLite 内部表**。`sqlite_sequence` 是 `AUTOINCREMENT` 的内部记账表，PG 侧对应的是 sequence 对象而非表，不计入任何对账。

| 端 | 业务表 | `signal*` 表 | `llm_usage` 列数 | 相对生产 |
|----|--------|--------------|------------------|----------|
| Vultr 生产（Docker 卷 `looma-zervi_backend-data/_data/looma.db`） | 50 | 仅 `signal_ingest` | 11（无 `cached_tokens`） | 基准 |
| 天翼生产（同路径卷） | 50 | 仅 `signal_ingest` | — | 无差异（同口径） |
| **本机 dev**（`~/Projects/looma-zervi/backend/data/looma.db`） | **52** | `signal_ingest` + **`signal_outbox`** + **`signal_dlq`** | **12（含 `cached_tokens`）** | **+2 表 +1 列** |
| `genzltd_schema_v0.2.sql`（PG 蓝图） | 50 | 仅 `signal_ingest` | — | 表名 = 生产 50 张业务表 |

> 原始 `sqlite_master` 计数各含 `sqlite_sequence` 1 张（生产 51 / dev 53），已按上述口径剔除。

**定性**：本机 dev 比生产多 2 张表 + 1 列，是**「边开发边测试」策略下的正常前瞻**——dev 先行落地 R2，尚未并入 `main`、未上生产。**既不是真源分叉，也不是错误**。

**增量来源**：R2「GFCC 出站信号 outbox + DLQ」建表迁移，分支 `wip-signal`、commit `7adb7f6`（2026-09-01）。硬证据：`git branch --contains` 仅命中 `wip-signal`；`git merge-base --is-ancestor 7adb7f6 main` = **NO**。

> 取证边界：该 commit 只存在于 `~/THOMAS/looma-zervi` 一棵树；`~/Projects/looma-zervi`（dev 库所在树）中不存在该对象，也检索不到 `signal_outbox` 建表文本。故可确认「该特性仅落在该分支」，但 **dev 库中这两张表的具体产生路径未取证**，不作结论。
