# 探针：真实简历验证 — 合规范围与设计输入

> 状态：**探针（Proposed，待评审）** · 作者：`szjason72`（执笔：Dudu） · 日期：2026-09-10
> 一句话：**真实简历能补的是「声明验证」缺口（自述与他源是否一致），补不了「同行评价」缺口（谁认可谁）；而且现有实现里再多简历也不会改变输出 —— 本探针只在「验证」范围内使用真人数据，且必须先过授权与门控。**

---

## 一、为什么开这份文档（治理依据）

本文件是 [ADR-0011](adrs/0011-dsh-bridle-freeze-career-cosmos.md) 第 29 条要求的那份**新开文档**：

> 人才/简历的合规能力走 **信任层**（Wukong 门控 + `genz-verify` 对拍），不是把简历导入 bridle 建第二座知识库。进口脱敏脚本若要做，须**新开文档**立项，不得声称「docs 里设计已定、只差代码」。

同时遵守 ADR-0011 第 16 条的禁止事项：不得把「简历脱敏脚本」写成尚未落地、却仿佛已是 docs 口径的工序。

缺口本身在 [实证记录-诗词语料共识评价模型沙盘-20260909.md](实证记录-诗词语料共识评价模型沙盘-20260909.md) 第 16 行已自认：

> 直接拿真实简历验证这个假设有两个障碍：**合规风险**（PIPL 敏感个人信息）和**数据缺失**（我们手里没有带同行互评记录的简历库）。

**状态纪律**：本文为 Proposed，不是 90 天承诺，不声称「设计已定、只差代码」。涉及契约字段的新增/变更须走 `GenzLTD/looma-zervi` 契约 PR + 评审。

## 二、范围声明

### 2.1 本探针回答的两个问题

| # | 问题 |
|---|---|
| Q1 | 真实简历能否在**不产出评价分**的前提下，为 T空间 HR 视图提供可审计的「声明验证」信号？ |
| Q2 | 该能力能否落在**已有**信任层契约（attestation / share_code / 审计）之内，而不是新建一座简历知识库？ |

### 2.2 越界清单（明确不做）

| 不做 | 理由（真源） |
|---|---|
| 产出「同行认可度 / 信任分 / 信用分」 | 简历是自述，用于评分 = 放大自我背书，与「防自证」冲突；且踩「几何层 ≠ 信任」红线 |
| 用共事重叠（同公司同时段）推认可度 | 那是结构边，不是评价边 —— 六度距离问题的重演 |
| 把简历导入 dsh-bridle / 建第二座知识库 | ADR-0011 第 29 条明文禁止 |
| 使用非本人授权的简历（他人简历、内部 HR 库、抓取或下载件） | PIPL；且尽调不可辩护 |
| 未脱敏数据出本机 / 出租户 | [新一代智能大脑架构设计.md](新一代智能大脑架构设计.md) 第 167–169 行：边缘层本地存储，仅「已脱敏共识子图」上云，走 Wukong 门控 |

## 三、缺口诊断：为什么简历填不上「评价来源缺口」（技术论证）

### 3.1 评价边需要什么，简历提供什么

| 维度 | 评价边需要 | 简历能提供 | 结论 |
|---|---|---|---|
| 主体方向 | **他述**：A 评价 B | **自述**：B 写 B | 结构不同 |
| 类型 | 认可 / 背书 / 推荐 / 悼念 | 无 | 缺 |
| 强度与时点 | 当时认可 vs 滞后声誉 | 时间轴有，强度无 | 缺 |
| 授权前提 | 评价者愿意公开 | 无 | 缺 |
| 可算的边 | —— | **共事重叠**（同公司同时段） | 仅结构边 |

### 3.2 一个关键的实证发现：现有实现里「多跑简历」的边际收益为零

核对 `GenzLTD/looma-zervi`（本地副本，核对日期 2026-09-10）后确认：简历→信任的桥**已经存在并在运行**：

| 环节 | 实现位置 |
|---|---|
| 简历上传 / 解析 / 薄入库 | `backend/src/api/routes/resume_routes.py:148`（`/v1/resume/upload`）、`:114`（`/parse`）、`:332`（`/ingest`） |
| 授权门控 | `resume_routes.py:116` 等：`@require_consent("jobseeker_core")`；实现见 `backend/src/compliance/consent.py:263` |
| 写入信任记忆 | `resume_routes.py:57` `insert_trust_memory(session_type="resume")` |
| 生成 attestation | `resume_routes.py:69` → `backend/src/agents/trust_agent.py:67` `generate_attestations` |
| 简历分支规则 | `trust_agent.py:106–136` |

而 `trust_agent.py` 对简历的判定是：

- 仅简历 → `verification_status = "weak"`，`confidence = 0.35`；
- 简历 + 匹配扫描 → 仍 `weak`，`0.45`；
- 代码注释原文：**「Self-claim alone never becomes "verified".」**（`trust_agent.py:108`）。

**规则只判断「有没有」简历记忆，不判断「有几份」。** 因此：

> 再上传 10 份真实简历，输出仍是 `weak 0.35`。**「拿更多简历跑一跑」不可能把评价来源缺口补上，也补不上验证缺口 —— 唯一能把 `weak` 抬起来的动作是引入「自述之外的独立来源」。**

### 3.3 四条红线（本探针不可越线）

1. **几何层 ≠ 信任**：共事重叠只是图上的距离，不是认可；
2. **防自证**：自述内容不得无条件提升可信状态 —— 这一条**代码里已落实**（见 3.2）；
3. **匿名 ≠ 不可审计**：可以匿名展示给第三方，但内部每一步必须有来源可溯；
4. **图级脱敏缺口**：单条脱敏不等于整图不可识别，跨源拼接可能重识别 —— 本探针**不做跨源画像拼接**。

### 3.4 结论

> **简历能补「验证」的洞，不能补「评价」的洞。**
> 评价来源的三条正路 —— 产品内互评采集（`fleet_consensus` / `match_consensus` 的输入）、权威锚定（`credential`）、授权背调对证 —— 都要产品或合作侧动作，本探针不声称替代它们。

## 四、探针设计（数据流与最小闭环）

### 4.1 输入：仅「本人授权上传」

| 项 | 现状 | 本探针要求 |
|---|---|---|
| 来源 | 候选人本人上传（`/v1/resume/upload`、`/ingest`） | 保持；新增来源须逐项过合规 |
| 授权 | `@require_consent("jobseeker_core")`，未授权返回 403 + `error="consent_required"`（`consent.py:274–288`） | 保持，作为硬闸门 |
| 使用范围 | `consent.py` 模块头已写明「PIPL：单独同意 / 目的限定 / 可撤回」 | 明确「仅用于声明验证，不用于评分/画像/推荐」 |
| 存储 | 简历 markdown **全文**存 `documents.metadata` JSON，随 `/list`、`/analysis` 返回（`resume_routes.py:243–246`、`:288–291`、`:520–529`） | **待决 5**：与「最小化 / 加密存储」有差距 |
| 撤回 | `DELETE /v1/resume/<resume_id>`（owner-scoped，`resume_routes.py:612`）+ 同意 `revoke()`（`consent.py:148`） | 需补：撤回后的信任记忆/attestation 处置链路 |

### 4.2 抽取与归一化

现状已做：MarkItDown（PDF/DOCX → markdown）→ LLM 结构化（`resume_routes.py:197–274`）→ `extracted` JSON 落库。本探针在其上要求每条 fact 带**原文位置**（页码/段落），供 4.4 溯源。

### 4.3 交叉印证（本探针的技术核心，也是当前完全缺失的一环）

来源分层（独立性自下而上）：

| 层 | 来源 | 独立性 | 现状 |
|---|---|---|---|
| S1 | 简历自述 | 最低（self-attested） | ✅ 已有 |
| S2 | 本人其他授权的公开来源（主页 / 作品集 / 代码仓） | 中 | ❌ 无 |
| S3 | 权威来源（企业邮箱验证 / 学历库 / 证书签发方） | 高 → 对应 `evidence_type=credential` | ❌ 无（契约有 `credential`，代码从未产出） |
| S4 | 第三方书面确认（需对方本人授权） | 高，但已接近背调 | ❌ 无（待决 2） |

一致性判定维度（先规则、后模型）：

- **时间轴重叠**：同一时段出现两个全职单位 → 冲突；
- **职级序列单调性**：职级跳变无解释 → 待核；
- **实体存在性**：公司 / 机构实体是否可解析；
- **技能–产出可达性**：声明技能与声明产出是否自洽。

输出三态（**禁止**把任何一态折算为「可信度分」对外输出）：

| 状态 | 判定 | 建议处置 |
|---|---|---|
| `consistent` | ≥2 个独立来源指向同一事实 | 发 attestation（可高于 `weak`） |
| `single_source` | 仅自述 | 保持 `verification_status=weak`，标注「仅自证」 |
| `conflict` | 来源互相矛盾 | **不发 attestation**，转人工复核（人类在场，ADR-0009 第 32 条） |

### 4.4 输出落点（契约映射）

真源：`GenzLTD/looma-zervi` → `backend/contracts/trust.v1.json`

| 契约字段 | 现状 | 本探针需要 | 是否需变更 |
|---|---|---|---|
| `claim_type` | `identity / collaboration / communication / influence` | 复用（履历类走 `identity`） | 否 |
| `evidence_type` | `quiz / fleet_consensus / dialogue_analysis / share_signal / credential` | **代码已在用契约没有的值**（见下） | **是** |
| `verification_status` | `verified / verified_by_authority / weak / unverified` | 复用；`verified_by_authority` 仅接 S3 时用 | 否 |
| `evidence_refs` | `trust_memories.id` 列表 | 复用（溯源） | 否 |
| `signature` | Ed25519，第三方可离线验签 | 复用（`GET /v1/trust/.well-known/public-key`，`trust_routes.py:220`） | 否 |
| `share_code` 审计 | `verifier_info / accessed_at / attestations_viewed / share_code_used` | 复用为「可回放」证据 | 否 |
| 授权门控 | `error_codes.consent_required` | 复用为授权闸门 | 否 |
| 撤回删除 | `DELETE /v1/trust/share-code/{code}`（`trust_routes.py:185`） | 复用（另需数据删除链路，待决 5） | 部分 |
| 人工复核 | 无 | `conflict` 处置队列 | **是**（产品侧，待设计） |

#### 4.4.1 已存在的契约漂移（必须先治理）

`trust_agent.py` 实际产出的 `evidence_type` 与契约 enum **不一致**：

| 代码产出（`trust_agent.py`） | 契约 enum 是否包含 |
|---|---|
| `quiz`（`:96`） | ✅ |
| `resume`（`:113`、`:117`） | ❌ **缺失** |
| `match_scan`（`:121`） | ❌ **缺失** |
| `fleet_consensus`（`:165`） | ✅ |
| `match_consensus`（`:165`） | ❌ **缺失** |
| `dialogue_analysis`（`:193`） | ✅ |
| `share_signal`（`:218`） | ✅ |

**关键观察**：
- 本探针**不需要**新造 `resume_claim` 之类的枚举值 —— 代码早已在用 `resume`，缺的是把它写进契约（或反过来收敛代码，方向由评审定，见待决 1）；
- 契约里 `fleet_consensus`（共识通道）**已存在** —— 缺的**不是契约字段，而是它的输入数据来源（评价边）**。本探针不去伪造这份输入。

## 五、合规范围（硬前置，不是可选项）

### 5.1 适用与分类

简历含工作经历、学历、联系方式，属**个人信息**；涉及精确联系方式等可能升格为敏感个人信息。PIPL 下需做**个人信息保护影响评估（PIA）**，本探针把 PIA 作为**开工前置**而非交付物附件。

### 5.2 授权四件套

| 项 | 现状 | 差距 |
|---|---|---|
| 明示同意 | ✅ `consents` 表（含 `purpose`、`ip`、`user_agent`、`granted_at`） | 无 |
| 目的限定 | ✅ 模块级声明；`scope` 粒度存在 | `purpose` 字段是否真被逐次使用，待核 |
| 最小化 | ⚠️ 简历 markdown 全文入库并在 `/list` 返回 | **待决 5** |
| 可撤回 | ✅ `revoke()` + `DELETE /v1/resume/<id>` | 撤回后 attestation / trust_memories 的级联处置缺失 |

### 5.3 本地优先

对齐 [新一代智能大脑架构设计.md](新一代智能大脑架构设计.md) 第 167–169 行：个人完整图谱本地（边缘层）存储，仅「已脱敏共识子图」上云，走 Wukong 门控。**未脱敏简历不出本机** —— 现 `documents` 表落地本机 DB，方位正确，但需补「不出租户 / 不上云」的显式约束。

### 5.4 跨境

若涉及海外人才（looma 有跨境匹配场景），个人信息出境需单独同意 + 出境合规路径。本期探针**默认不跨境**，跨境须另立评估。

### 5.5 与 90 天硬动作 5 的关系

[聚焦决策-Career-Cosmos-90天.md](聚焦决策-Career-Cosmos-90天.md) 第 42 行：硬动作 5 含**人力资源服务许可证**。若探针演进到 S4（第三方书面对证 / 背调），是否落入「人力资源服务」监管边界，须在许可证进度确定后再定（待决 3）。
